# Architecture decision record (2026-11-12)

1. **D-001 – Public source commit now authorized.** Connected `ZX7-Labs/runtime-assurance-lab` on `main` had just `README.md`; GitHub reports `visibility=public`. User explicitly accepted public visibility and authorized applying the prototype on 2026-11-12. Only source+synthetic-fixture publication is allowed; no releases, deploys, visibility changes, paid services or secret access.
2. **D-002 – B over A.** Test a bounded event-sourced cross-plane correlation contract before any Kubernetes operator. A cluster-wide reconciler duplicates proven upstream observer behavior and requires unjustified privileges. See `PLAN.md`.
3. **D-003 – No new signing infrastructure.** For offline signature-attack tests use existing PyCA Ed25519 primitive with generated ephemeral keys. Intended future interoperability is Sigstore bundles, independent trust roots, and a durable transparency/immutable store—not this toy journal protocol.
4. **D-004 – Fail closed on weak evidence.** Matched but `declared`/`inferred`/`unresolved` models are `UNKNOWN`, not `OK`; old observations `STALE`. Provenance claims aren't proof of execution, and `verified` comes from a trusted adapter in a future system, not an arbitrary payload.
5. **D-005 – Policy isolation.** Pure evaluator controls `OK/DRIFT/UNKNOWN/STALE`; signed decisions must be recomputed from signed parents. Independent clock/policy pin required for real assurance.
6. **D-006 – Public-source licensing undecided.** Do not add an OSI license file or promise open-core/dual licensing before legal/product evidence. Third-party libraries remain under their own licenses.
7. **D-007 – Evidential measurement.** Synthetic 700-case baseline and microbench are not live tool or real detection-latency results. Use labeled cases and report throughput/CPU/memory with exact method; real comparisons remain blocked.

8. **D-008 – Strict untrusted JSON boundary.** Reject duplicate object keys, nonfinite values, invalid Unicode and files above 8 MiB. Bound proof journal to 10,000 events and validate anchor/trust containers. This avoids parser differentials and accidental excessive resource use in the offline CLI, but is not a production DoS solution.

9. **D-009 – Source-specific offline adapter before cluster connectivity.** Pinned Google `k8s-aibom` tag `v1.6.2`, commit `47bf6418e40eee22905973528b879dc075181b3f`, and its `aibom.k8saibom.dev/v1beta1` Go API. Build only a local JSON CR bridge; no K8s watches, collectors, deployment, or CRD write operations. Source status is an inventory claim and cannot establish a crypto-verified model identity.
10. **D-010 – Explicit evidence gaps beat inference.** `AIBOMSummary.models[].identity` is not a model digest; `lastReconciled` is not inference execution time; the CR summary does not carry the AICR recipe digest; `signed=verified` must not be trusted as a verified signature without independent verification. Leave unsupported normalized fields null. Inline BOM SHA-256 confirms internal consistency only, not publisher authenticity.
11. **D-011 – Strict decision schema.** Semantic verification rejects even signed decision payloads with extra fields, to prevent plausible but unevaluated assurance claims. Existing optional synthetic `fixture` label remains supported; the proof is still not a Sigstore artifact or trust anchor.
12. **D-012 – CPU-only public CI before real-cluster collection.** Run first-party SHA-pinned checkout/setup-python on standard `ubuntu-24.04` GitHub-hosted runners in a 3.11/3.13 matrix, `contents: read` only, checkout with `persist-credentials: false`, no secrets, no uploads or releases, and a 10-minute per-job limit. `pull_request` (not `pull_request_target`) handles untrusted contributions. Check existing synthetic baseline reports without claiming fresh performance measurements or cluster evidence. Test dependencies are version-constrained but not hash-pinned, so PyPI/build-time supply-chain risk remains. Public standard runners are documented free; prohibit larger runners.
13. **D-013 – Bind exactly, never infer execution (M3).** NVIDIA AICR v1.2.0 `RecipeResult` v1 has recipe-level component refs and platform criteria, not a per-workload attested model execution. Only accept locally supplied JSON recipe bytes with an explicit SHA-256 pin matching the separate intent input. An attacker can fabricate both pin and bytes: leave provenance and runtime truth unverified, and do not promote a healthy AIBOM summary to `OK`. Fail closed on ambiguity; the current CLI is an interoperability experiment, not a security root.
14. **D-014 – Shared strict JSON and bounded reads.** Reuse a single strict JSON decoder for CLI, AICR and embedded AIBOM data; reject exponent overflow (e.g. `1e999`) as nonfinite. Bound reads in one operation rather than trusting a potentially racing file size check. Python integer size limits remain runtime-dependent.

15. **D-015 – Recompute source-derived reports rather than trust an evaluator claim (M4).** `receipt-offline` includes exact source-byte digests, pinned adapter identifiers, policy ID, separately supplied clock, decision and limitations. `replay-offline` demands original source bytes, expected recipe pin and clock as **separate inputs** and reconstructs the full report. A receipt by itself is neither signed nor independently sourced; only independently anchored sources and trusted source-signing verification can establish authentic provenance in future G4 work. Avoid building another signing service and keep G4 blocked.
16. **D-016 – JSON type identity and no overwrite.** JSON comparison must be representation/type-preserving: Python `True == 1` makes ordinary deep dict equality unsafe for proof validation. Reuse the existing deterministic canonical serializer for replay equality (not RFC 8785). Create receipt output exclusively (`xb`) to avoid overwriting prior receipts or raw input evidence; a failed replay must not repair a corrupted file.
17. **D-017 – A weak comparator is not enough to prove value (M5).** Introduce a separate same-input reference policy as a negative control; parity is expected and must be reported as no established incremental signal. The earlier naive baseline is intentionally constrained and is not NVIDIA AICR, Google k8s-aibom or a real competitor. Only a representative, authorized upstream run can establish differentiation.
18. **D-018 – Distinguish latent drift from reportable drift.** Synthetic oracle ground truth may include hidden deviations that a detector **cannot** see due to missing, expired or future evidence; counting all `UNKNOWN` as detected drift inflates claims. Report observable-condition drift recall separately from latent-case recall and unsupported-`OK` count; all "verified" fields remain unauthenticated synthetic inputs.

19. **D-019 – Distinguish source assertion from authenticated verdict (M6).** The historic `verified` model label is untrusted. Public `evaluate()` now returns `UNKNOWN` for otherwise conforming or drifting untrusted claims; claim-only comparison survives only as an internal historical benchmarking primitive. Requiring detached signature + externally pinned trust/intent + external monotonic checkpoint is the only offline positive `evaluate-authenticated` path. Never accept a caller-provided `trusted=True` Boolean.
20. **D-020 – Minimal offline gate before external transparency architecture.** Selected an Ed25519 domain-separated, version-pinned, exact-byte signed observation over a bounded trust manifest. Source/workload allowlist, fixed sequence/previous head and externally supplied current time must agree. This is a deliberately restricted integration probe, not a Sigstore, TUF or Rekor implementation; real-world auth requires independently maintained identity/trust policy and durable rollback protection.
21. **D-021 – No silent protocol compatibility.** Updated policy version to `ral-intent-observation-v2-provenance-gate`. Historical M5 outputs remain in `results/incremental_value.json` as evidence of the old unsafe behavior; newly computed claims-only comparisons are explicitly labeled. A source-authenticated `OK` asserts agreement with an authorized signer's statement, **not GPU/model execution or Sigstore model artifact verification**.

22. **D-022 — M7 bounded transactional checkpoint simulation, not a trusted anchor.** Offline tests now require an independently held SHA-256 of the entire previous state alongside pinned root/intent; local SQLite `BEGIN IMMEDIATE` serializes verification and advancement and commits before returning success. Operator-only bootstrap cannot overwrite a stream. A real external monotonic CAS/transparency authority was evaluated but remains blocked by G4 infrastructure and source provenance. Both the DB **and** its external digest can be rolled back by an attacker controlling both; no automatic local fallback is allowed. Trusted upstream Sigstore/AICR semantics remain the eventual integration target. No additional external dependencies or cryptographic formats.


## D-008 (2026-11-12): pause standalone product expansion pending upstream value proof

**User constraint:** Do not keep building a system that provides no real additional benefit.

**Alternatives:** A) add more prototype control, signing, rollback or inventory features; B) audit upstream overlap, create a machine-checkable research NO-GO gate, demand blinded real upstream comparison before engineering expansion. **Chose B.** Existing NVIDIA AICR, Google k8s-aibom and Sigstore/policy tooling already provide most of those primitives. M5 600-case same-input independent reference comparator produced 0 differences; there is no observed incremental efficacy versus upstream, because no actual upstream executable comparison has yet occurred.

**Scope of decision:** `PAUSE_PRODUCT_BUILD`, not an irreversible claim that cross-plane assurance has no potential value. Only G4 evidence acquisition/analysis, independent trust/security review, and prospective customer research may reopen the investment decision. Preserve M1–M7 experiments as research; no production assurances, licensing commitments, new controllers or vendor-specific reimplementations.

## D9 — research preflight instead of redundant production code (2026-11-12)

- **Alternatives considered:** A) create a new Kubernetes observer/source authority or duplicate BOM extraction; B) add another synthetic benchmark and treat it as product progress; C) cross-check **actual pinned public upstream test assets** and write the independent real-validation protocol without adding product runtime behavior.
- **Decision: C.** The existing Google golden CycloneDX BOM already carries a container SHA-256 and model evidence locators. The current RAL AIBOM adapter only uses conservative summary fields and cannot authenticate or promote that image digest, so a new extractor would duplicate upstream inventory. NVIDIA public RecipeResult fixture demonstrates resolved component intent, not a common live deployment. Offline test assets do not supply the trusted source/physical runtime bridge.
- **No-go remains:** `PAUSE_PRODUCT_BUILD`. Inability to demonstrate a fair, novel increment and independently protected provenance outweighs feature accumulation. Public source file hashes verify byte identity relative to a known Git tree, not signer or runtime identity. The operator must own real G4 trust/state before any real `OK` verdict.
- **Security/operational boundary:** Network fetch is opt-in in a segregated public-research GitHub CI job; pytest, application code and smoke are offline; exact URL allowlist/commit pins, bounded downloads, no redirects, no credentials, no cluster, no new package. External network availability can cause research CI to fail without implying a product logic failure. No provider binaries are run.

## D10 — accept upstream-local manifest component without inventing trust (M9)

First live public-fixture CI exposed an AICR v1.2.0 `RecipeResult` schema mismatch: `componentRefs.source=""` is permitted and appears in official local-manifest components. Rejecting every blank string made RAL **less compatible with existing NVIDIA data**. We narrowly relax it when bounded nonempty `manifestFiles` exist, add a limitation `AICR_LOCAL_MANIFEST_SOURCE_UNATTESTED`, and retain strict rejection otherwise. This is compatibility repair, not new product scope or evidence that model execution was observed.

## D11 — prepare operator G4 evidence custody instead of reimplementing upstream (M10)

Alternative A was a new cluster collector plus in-house signing and certificate verifier; rejected because NVIDIA AICR and Google k8s-aibom already supply specialized inventory/verification and because an unanchored reimplementation cannot prove runtime truth. Alternative B is an explicitly non-authorizing offline handoff format that consumes existing source files and *operator-held* pins while awaiting actual upstream Sigstore/bundle and Kubernetes API provenance. Chose B; it is a limited research/test bridge, not a third evidence authority.

A SHA-256 pin matching input bytes means integrity relative to the selected pin, not upstream authorship. An attacker who supplies both the file and its pin still cannot obtain `g4_authorized=true`; in fact the handoff CLI has no successful authorization exit. AICR `RecipeResult` does not natively bind a specific Kubernetes workload at runtime. The script refuses to create that linkage by inference; source authenticity, independent ownership and actual model execution remain outside this offline interface. No new product/runtime feature, deployment or license grant is authorized by M10.
